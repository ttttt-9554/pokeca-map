# ゲリラ監視の実行履歴

アメニティードリームの毎分監視と、通知待ちの毎分再確認は継続する。
通知待ちがない場合は `guerrilla-push` の起動を省く。
保留・再試行で実行時刻を過ぎた通知と、期限切れの処理中通知があれば、従来と同じ経路で起動する。
無効な購読先のみの場合は起動しない。検知時の即時通知、Discord通知、再送の仕様は変更しない。

毎時17分に、この監視・Push送信・整理自身のCron実行履歴を確認する。
正常終了から24時間を過ぎた履歴は、日本時間の日別の件数・最初と最後の実行日時・総実行時間へ集約する。
直近約1日分の詳細、失敗・実行中・時刻が不正な履歴は残す。他のCronジョブは対象外。
削除と集計は同一トランザクションで行い、集計に失敗した場合は詳細も削除されない。

日別集計は `private.guerrilla_run_log_daily_v1` に保存し、データベース管理者のみ参照できる。
販売検知、商品ごとの在庫状態、通知キュー、通知の送信履歴は整理しない。

Supabase基盤のEdge Function起動ログ・HTTPアクセスログは独立したログで、このSQLでは削除しない。
空のPush呼び出しがなくなる分、今後の件数を減らす。毎分の在庫確認に必要な起動ログは継続する。

検証: `scripts/test_guerrilla_log_retention.sql` は隔離したPostgresで実行する。外部通信・実通知は行わない。
