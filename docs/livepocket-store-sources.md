# LivePocketの店舗取得元

DiscordはURLと商品情報の発見に利用し、投稿本文・見出し・埋め込みの店舗名や都道府県を店舗登録に利用しない。
公式イベントページの対象店舗、チケットの店舗選択肢、店舗名ラベル、概要の会場を取得する。
会場欄の店舗名・都道府県・住所を、販売元の法人名や地図リンクと区別する。店舗名を囲うspan/リンクにも対応する。
同じイベントURLの公式タイトルに店舗名が明記されている場合も補助として利用できるが、取得済みの正式会場をタイトルの略称で上書きしない。
取得した公式店舗一覧は、Discord由来の店舗や以前の未確認一覧へ足し合わせず、置き換える。

公式ページで特定できなければ店舗・地域を未確認にする。以前の公式取得結果や手動確認済みの値は保持する。
管理画面の手動修正は従来どおり優先され、確認済みの店舗CSVは維持する。
公式ページで得た店名に対する、既存の一意な店舗マスター地域補完は継続する。

公開データには `store_location_source` と `store_location_url` を付ける。
店舗マスター同期はLivePocketについて、この根拠が同じイベントURLを指す公式取得・手動確認済み店舗だけ取り込む。
外部抽選やアプリ抽選の登録方法は変更しない。既存の店舗マスターや応募履歴を自動削除しない。

以前の混在データは公式確認待ちへ戻す。締切が過ぎていないイベントを通常収集で最大8件ずつ確認し直す。
タイトルの略称しかない場合と、店舗の地域が未取得の場合も再確認対象とする。旧地域参照CSVにだけ残る店舗は再登録せず、ほかの抽選の収集を停止させない。
概要に通販・オンライン会場が明記され、発送を行う商品抽選は、サイト内の通販名またはショップ名を登録し、地域を全国とする。実店舗の法人名を店舗名にはしない。
イエローサブマリンは、同じ公式イベント本文に取扱店舗全店統一の抽選と明記される場合に限り、既存の確認済み22店舗を参照する。
同じ実行で取得したページは再利用する。取得失敗時は6時間空け、アクセス制限時は通常の全体クールダウンに従う。
締切済みの過去イベントを、この変更のために巡回し直すことはない。

検証: `PYTHONPATH=scripts python -m unittest scripts/test_livepocket_site_stores.py scripts/test_livepocket_page_locations.py`
